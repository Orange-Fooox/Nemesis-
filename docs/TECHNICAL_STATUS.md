# Технический статус

## Подтверждённая база: v0.2

Известный файл прототипа: `NEMEZIDA_Roblox_Prototype_v0_2.rbxlx`.

Известная структура скриптов внутри проекта:

```
StarterPlayer/
  StarterPlayerScripts/
    NemezidaCamera.client.lua
    NemezidaControls.client.lua
StarterGui/
  NemezidaHUD.client.lua
ServerScriptService/
  NemezidaWorld.server.lua
  NemezidaCombat.server.lua
  NemezidaEnemyAI.server.lua
```

### Что есть в v0.2

- Арена примерно 150 × 150 studs.
- Периметр стен и базовые руины.
- Шесть тестовых противников.
- Генератор мира создаёт `Workspace.NEMEZIDA_WORLD` и пересобирает его при запуске сервера.
- Камера, управление, HUD, серверная боевая логика и AI противников.
- Боевая система использует CollectionService-теги и проверяет противников в пределах примерно 8 studs перед игроком.

### Атрибуты противников

Известные атрибуты:
- `NemezidaEnemy`
- `EnemyType`
- `Damage`
- `AttackRange`
- `AttackCooldown`
- `AggroRange`

### Известное ограничение v0.2

Текущий AI ищет ближайшего игрока в пределах `AggroRange` и может преследовать его автоматически. Это расходится с целевым дизайном, где враг должен реагировать на нападение игрока. Исправление запланировано для следующей версии.

### Не включено / не подтверждено

- Нет подтверждения, что v0.2 была открыта и протестирована в Roblox Studio в ходе переноса.
- Большая стартовая зона 420 × 420 studs не реализована в подтверждённой v0.2.
- NPC, восемь интерактивных сундуков и кошелёк с GUI относятся к плану v0.3.
- Кастомная модель героя и полный набор уникальных моделей врагов остаются требованиями к дальнейшей разработке, а не подтверждёнными функциями прототипа.

Они пока не включены в этот репозиторий. Добавить их в `Roblox/releases/` после восстановления доступа к бинарным файлам. При необходимости большие файлы можно хранить через Git LFS или GitHub Releases.

## Принципы разработки

1. Сервер авторитетен для урона, состояния врагов и наград.
2. Клиент отвечает за ввод, камеру и отображение HUD.
3. Генератор мира должен создавать одну управляемую корневую модель.
4. Новые системы документировать и проверять в Roblox Studio.
5. Не отмечать функцию готовой только потому, что она есть в плане.
