# NEMEZIDA — предварительный план переноса на Unity

Статус: исследовательский план, перенос не начат. Текущий рабочий проект остаётся Roblox.

## Реалистичная оценка
Перенести проект на Unity можно, но это полноценная портирующая разработка, а не конвертация Place-файла одной кнопкой. Roblox Place (.rbxlx/.rbxl) не является Unity-проектом. Сцены, скрипты Luau, сервисы Roblox, физика, персонажи, UI, сетевой слой и сохранения придётся переносить отдельно.

## Что можно сохранить
- игровую концепцию, лор, дизайн регионов и подземелий;
- балансные таблицы, характеристики, формулы урона и описания предметов;
- изображения, исходные текстуры и модели, если их можно законно экспортировать и использовать вне Roblox;
- структуру встреч, NPC, квестов и прогрессии;
- документацию и тест-кейсы.

## Что придётся переписать
| Roblox | Unity |
|---|---|
| Luau Script / ModuleScript | C# scripts |
| Workspace / Model | Scene / GameObject / Prefab |
| Humanoid / Character | CharacterController или Rigidbody + собственная система |
| RemoteEvent / RemoteFunction | Netcode for GameObjects или другой сетевой слой |
| ReplicatedStorage / ServerStorage | Addressables, ScriptableObjects и runtime-сервисы |
| DataStoreService | собственный backend или облачное хранилище |
| ProximityPrompt | собственная система интеракций |
| Roblox UI | Canvas UI / UI Toolkit |
| PathfindingService | Unity NavMesh |

## Ассеты и лицензии
MeshPart, MeshId и TextureId не превращаются автоматически в Unity-ресурсы. Нужно проверить права и возможность экспорта каждого источника, выгрузить mesh/texture-файлы, восстановить материалы и проверить масштабы, pivots, normals, colliders и LOD. Наличие ассета в Roblox не означает автоматически, что его разрешено использовать за пределами Roblox.

## Предлагаемая архитектура Unity
- Scenes/Bootstrap: загрузка конфигурации и переходы.
- Scenes/AshenHub: хаб и NPC.
- Scenes/Dungeons/PolygonCrypt: модульное подземелье.
- Scripts/Combat: бой, способности, урон и статусы.
- Scripts/AI: поведение NPC и врагов.
- Scripts/World: генерация, Seed, события и регионы.
- Scripts/Inventory: предметы, экипировка и лут.
- Scripts/Save: профили и сохранения.
- Data/ScriptableObjects: характеристики, предметы, враги и комнаты.

## Безопасный порядок портирования
1. Зафиксировать Roblox-версию как отдельную рабочую ветку и не прекращать её поддержку.
2. Сделать инвентаризацию скриптов, ресурсов, зависимостей и прав на ассеты.
3. Создать Unity greybox без внешних ассетов: управление, камера, одна комната и один враг.
4. Перенести боевую систему и AI, покрыть их тестами.
5. Перенести Polygon Dungeon после экспорта и проверки моделей.
6. Перенести хаб, NPC, UI, предметы и сохранения.
7. Добавить сетевую архитектуру только после решения, нужна ли Unity-версия одиночной или кооперативной.
8. Сравнить производительность и визуальное качество с Roblox-версией.

## Решение
Сейчас рациональнее продолжить Roblox-прототип: там уже есть исходники и импортированные ассеты. Unity стоит рассматривать как отдельную параллельную ветку после стабилизации вертикального среза (хаб → NPC → dungeon → бой → награда → сохранение). Не удалять и не переписывать Roblox-проект ради экспериментального порта.
